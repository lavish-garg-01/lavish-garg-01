# V2 database ownership map

| Domain owner | Tables | Data class | Initial retention / mutation rule |
| --- | --- | --- | --- |
| Identity | `accounts`, `users`, `account_memberships`, `external_auth_identities` | Candidate-private / security | Account lifecycle; membership changes audited |
| Entitlements | `plans`, `features`, `plan_entitlements`, `subscriptions`, `entitlement_overrides`, `usage_counters` | Operational and account-private | Current configuration plus billing/audit retention; no `isPaid` column |
| Documents | `documents` | Candidate-private metadata | Object bytes live behind `ObjectStoragePort`; deletion propagates to storage |
| Job Intelligence | `companies`, `job_sources`, `jobs`, `job_source_snapshots`, `job_source_job_states`, `job_dedupe_keys`, `job_facets`, `job_fact_provenance`, `job_lifecycle_events`, `job_ingestion_receipts`, `job_source_scan_receipts`, `skills`, `job_skills`; candidate-owned `candidate_search_profile_versions`, `candidate_search_profiles`, `candidate_search_profile_receipts` | Public/shared job evidence plus candidate-private search preferences | Raw evidence stays behind object storage; changed snapshots, provenance, lifecycle and receipts are append-only; search-profile versions use OCC/idempotency and account RLS |
| Candidate Truth + repeatable identity | `candidates`, `canonical_fields`, `canonical_answer_policies`, `candidate_entities`, `candidate_entity_versions`, `candidate_entity_source_keys`, `candidate_answer_scopes`, `candidate_answer_versions`, `candidate_answers_current`, change sets/items, reversal sets/items/receipts, import preview runs/items/receipts, import apply runs/batches/items/reconciliations/receipts, runtime proposals, reviews, `application_entity_bindings`, `candidate_entity_operation_receipts` | Candidate-private; binding receipts value-free | Versions, change-set items, reversal/import/entity-operation audit are append-only; current projection advances only through Candidate Truth transactions; entity UUID is independent from profile/DOM order; bindings carry entity OCC revision but no candidate values; proposals expire |
| Application Intelligence | `applications`, `application_runs`, `application_checkpoints`, `application_events` | Candidate-private | Durable application lifecycle; verbose events receive bounded retention later |
| Verified Learning | `candidate_learning_run_receipts`, `application_execution_evidence`, `candidate_learning_observations`, `candidate_learning_submit_attempts`, `candidate_learning_checkpoint_receipts`; encrypted values remain in Candidate Truth-owned `candidate_answer_runtime_proposals` | Candidate-private values behind encryption; value-free operational evidence | Observations expire after seven days unless consumed; terminal observation evidence is immutable; checkpoint/submit/launch receipts are replay-safe and candidate-RLS protected |
| Strategy Intelligence | `ats_families`, `strategy_versions`, `strategy_observation_daily` | Value-free shared intelligence | Declarative MV3-safe plans and long-lived aggregates only |
| AI / Usage | `ai_usage_events` | Account-private usage metadata | Short detailed retention, later daily aggregates; no prompts or candidate answers |
| Operations | `idempotency_records`, `outbox_events`, `worker_jobs`, `feature_flags`, `audit_events` | Operational, references only | TTL idempotency, retry/dead-letter, value-free references and audit policy |

Indexes in `0001` correspond to initial hot queries only. Partitioning, BRIN, Redis, ClickHouse and OpenSearch are deferred until measurements justify them.

RLS is enabled for first-party account-owned roots in `0001`, later Candidate Truth/onboarding/search-profile tables, and all Phase-L verified-learning evidence tables. Nested tables still retain repository-level account authorization, and production Phase W must complete restricted-role grants plus live Supabase two-tenant penetration testing; the current schema is not a claim that production hardening is complete.
